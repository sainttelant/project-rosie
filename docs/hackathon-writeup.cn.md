# Project Rosie — 面向犬类的个性化癌症疫苗

*Gemma4Good · Health & Sciences 赛道 · Kaggle 黑客松 writeup*

**面向肿瘤科医生的 AI 临床助手——从兽医场景切入。从肿瘤 DNA 到可合成的 mRNA 疫苗只需数小时，Gemma 4 是任何兽医诊所否则无法雇用的那层智能。**

---

## 问题

2025 年末，一位来自澳大利亚的 AI 创业者、有 17 年经验的机器学习老兵，花三个月在一间大学研究实验室里，手工为他的狗 Rosie 设计了一支个性化新抗原癌症疫苗。**如果这是拥有他这种背景的人所需，那么对于一位没有 ML 训练的兽医肿瘤医生来说，可及性甚至不是一个"问题"。它是一堵墙。**

个性化新抗原疫苗是最有前景的新兴癌症治疗之一。但设计流水线——从测序好的肿瘤到可合成的 mRNA 构体——需要精通 pVACtools、NetMHCpan、密码子优化、IVT 化学，以及另外半打专业工具。兽医诊所没有这些人。所以今天本可以受益的狗得不到疫苗。

**Project Rosie 拆除那堵墙。** 它是一个面向肿瘤科医生的 AI 临床助手——首先为兽医医学构建，并有一条通往人类肿瘤学的直接转化路径。兽医上传一份肿瘤变异调用文件（VCF），流水线在云算力上不到一小时运行（每病例约 15 美元），四份产物出现在仪表盘上：

1. 一份排序好的个性化新抗原靶点列表
2. 一段可合成的多表位 mRNA 构体（FASTA）
3. 一份给兽医肿瘤医生的白话临床报告
4. 一份可直接邮件发给合同制造商的正式 mRNA 合成规格书

线上地址 **rosie.kiraklabs.com** · 公开演示 **rosie.kiraklabs.com/demo** · [Kaggle writeup](https://kaggle.com/competitions/gemma-4-good-hackathon/writeups/new-writeup-1777596440505)。

## 架构

| 层 | 技术 |
|---|---|
| 前端 + API | Vercel 上的 Next.js 16（App Router） |
| 鉴权、DB、实时 | Supabase（Postgres + RLS + Realtime） |
| 文件存储 | Google Cloud Storage |
| 流水线运行时 | Cloud Run Jobs 上的 Python（8 Gi、4 CPU、3 小时超时） |
| 变异注释 | Ensembl VEP（犬类 ROS_Cfam_1.0 缓存） |
| 新抗原预测 | 经 IEDB 的 pVACtools + NetMHCpan |
| 评分 | 透明的 Python 综合评分器（约 50 行） |
| mRNA 设计 | Biopython + 犬类密码子表 |
| 合成规格 | Jinja 模板（刻意*不*用 LLM 生成；见下文） |
| LLM 层 | **Gemma 4（`gemma-4-26b-a4b-it-maas`）via Vertex AI** |

流水线是一条确定性的 Python 脚本，在每个阶段发出 HTTP 回调。Next.js 前端通过 Supabase Realtime 订阅病例行。UI 的垂直时间线实时动画，无需轮询。

## 我们如何使用 Gemma 4

Rosie 不是一条在末尾挂上一个 LLM 的流水线。下面四个 Gemma 角色构成一个临床助手的架构：智能在运行*之前*（向临床医生提供建议）、运行*之后*（解读结果）、*交互式地*（响应临床判断）、以及*按需*（用白话回答问题）运作。合在一起，它们给兽医肿瘤医生一样他们从未拥有过的东西：跨整个病例的专家级 AI 推理。

我们把 Gemma 4 推入**一条确定性流水线真正无法执行**的角色：在流水线*之前*和*周围*推理，而不只是*之后*。

**角色 1 · 预检 VCF 顾问（主动）。** 当兽医上传一个 VCF 时，浏览器解析结构事实（变异数、INFO 键、样本列、体细胞标志是否存在、染色体、FILTER 值）并发送给 Gemma。Gemma 在用户烧掉一小时算力*之前*识别出 0–3 个会降低预测质量的问题。严格 JSON 输出，带安全解析回退。从不阻塞提交。

> *"这个 VCF 没有 SOMATIC 标志，也没有 NORMAL 列。它看起来像是胚系 + 体细胞混在一起。那会用非肿瘤突变抬高你的候选数。建议在提交前用配对的正常样本重新运行体细胞检测器。"*

**角色 2 · 多模态临床报告撰写者（被动）。** 流水线完成后，Gemma 多模态地读取候选 JSON、结合亲和力柱状图（PNG）和突变谱饼图（PNG），并撰写一份 400–600 字的白话临床报告。一个物种感知的系统提示会切换 DLA / HLA / FLA 术语，并按物种调整 IC50 解读。

**角色 3 · 敏感性解说者（交互）。** 在候选表下方，用户得到一个"What if?"面板，带两个滑块：IC50 阈值和肿瘤 VAF 阈值。当他们拖动时，保留/剔除的候选在客户端即时重新排序（每次刻度变动都不需要 Gemma 往返）。当他们点击*"让 Gemma 解读"*时，Gemma 写一段关于权衡的解读：

> *"提高结合和等位基因频率阈值的严格度会过滤掉你的 TP53 候选，只留下 PIK3CA 肽作为可行靶点。这缩小了你的新抗原池，并导致你的构体失去关键的 TP53 覆盖。"*

这把报告从一份静态文档变成兽医可以用自己的临床判断去追问的东西。

**角色 4 · 对话式病例助手（被动）。** 报告页上的浮动聊天组件。完整病例上下文（样本、顶级候选、临床报告）加载进系统提示。白话问答，数秒内完成。

### 我们刻意*没有*用 Gemma 做什么

mRNA 合成规格书是要逐字发给 CMO（Trilink、Genscript、Aldevron）的。我们最初让 Gemma 来写它。我们把它替换成了一个 **Jinja 模板**。原因如下：

> 一位看到幻觉出来的目录号、漂移的 QC 阈值、或含糊措辞（"请咨询你的生物信息学家"）的制剂科学家会否掉整个工具。这份文档里所有的可变性都是患者/病例数据。制造科学是固定的（CleanCap® AG cap1 / TriLink Cat# N-7413、100% m1Ψ 替换、SM-102 LNP 以 50:10:38.5:1.5 摩尔比、RIN ≥ 8.0 放行标准等）。模板化是正确的工具。

这种分工（**AI 负责解读，确定性代码负责合规**）也正是让工具日后能向监管者自圆其说的原因。流水线科学是可复现、可审计的；Gemma 是叠加在上面的解读层。

## 关键技术决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 输入格式 | VCF，而非 FASTQ | 把 Phase 1 的搭建复杂度降低约 60%。FASTQ 摄入作为 Phase 2 记录在案，带明确的采用上限数学（5% → 80% 的兽医诊所）。 |
| 合成规格 | Jinja 模板，而非 LLM | CMO 订单文档必须是确定性的；见上文。 |
| 流水线编排 | Cloud Run Jobs 上的 Python | 演示故事。Nextflow 是生产迁移路径。 |
| 克隆性 | 用 VAF 作代理 | PyClone-VI 是 Phase 2；VAF 是合理的黑客松代理。 |
| AlphaFold | 从 Phase 1 排除 | 以每病例 GPU 小时为代价换取约 5–10% 的排序精度提升。此刻 ROI 不对。 |
| 敏感性重排序 | 客户端过滤 | 零 Gemma 成本的即时滑块反馈。Gemma 仅在用户明确要求时解说。 |

## 我们克服的挑战

**物种感知的多模态落地。** 开箱即用的 Gemma 默认采用人类肿瘤学框架。系统提示模板中的物种切换会替换 DLA/HLA/FLA 术语、调整 IC50 解读阈值，并把报告落在兽医而非人类的措辞上。

**无轮询的实时流水线状态。** Cloud Run Jobs 在每一步之后发出一个阶段回调（Case Queued → Neoantigen Prediction → Candidate Ranking → Report Generation → mRNA Vaccine Design → Results Ready）；Supabase Realtime 把它们直接推入 React 树，实时动画化垂直时间线。

**演示数据质量。** 最初的犬类流水线运行只返回一个高置信度候选，产生视觉上很平淡的图表（一根实心柱、一个实心圆）。我们围绕合成 VCF 所针对的同样五个致癌驱动基因（PIK3CA、TP53、BRCA2、KIT、PTEN）合成了一个富集演示数据集，并重新渲染可视化，在不牺牲犬类叙事的前提下做出更有说服力的演示。

## 还缺什么（诚实章节）

- **早期 SME 验证。** Case 综合癌症中心的一位高级研究助理（生物信息学 + 统计遗传学背景）审阅了流水线——评估：可信的 MVP，有实质潜力。来自 OVC Guelph / OICR 比较肿瘤学小组的更深临床验证正在进行中。
- **Phase 1 从 VCF 开始。** 大多数兽医诊所从测序伙伴那里收到 FASTQ。FASTQ → VCF（BWA-MEM2 + Mutect2）是 Phase 2 最大的单一采用杠杆：约 5% → 约 80% 的可触达兽医诊所市场，代价是约 16× 算力成本和约 100× 存储。已记录在 README 中。
- **仅肿瘤样本处理。** 更推荐配对正常样本检测；仅肿瘤流程需要在排序中显式的置信度折减。预检顾问已经标记了这一点；Phase 2 会据此行动。

## 为什么这超越了黑客松

狗和人类共享 TP53、PIK3CA、BRCA2 以及许多其他致癌驱动基因。**犬类试验比人类试验更快、更便宜。每一个通过这条流水线的狗病例，在科学上都是临床前比较肿瘤学数据。** 狗的剧本会成为人类的剧本。

一个开放权重模型（Gemma 4）意味着诊所可以在本地运行 LLM 层。**患者测序数据永远不必离开大楼。** 这正是让它成为一个开源产品而非 SaaS 的原因。

这就是 Gemma4Good 在实践中的样子：一个真实的医疗工作流、真实的患者（先是四条腿的那种）、开放的代码、可自圆其说的工程、以及对自身局限的校准式诚实。Gemma 4 被用作一条确定性流水线周围的思考伙伴，而不只是末尾的一个文字工匠。

最能概括它是什么的框架是：**一个面向肿瘤科医生的 AI 临床助手，从那些无法为自己发声的患者开始。** 确定性流水线负责生物学——可复现、可审计、带公开阈值。Gemma 负责解读。这种分工也正是当时候到来时让工具能向监管者自圆其说的原因。
