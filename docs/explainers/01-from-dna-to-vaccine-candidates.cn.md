# 从 DNA 到疫苗候选——完整旅程

*写给没有生物学背景的读者。如果你是软件工程师，可以把这想象成追踪一个请求穿过一个分布式系统——只不过数据是一只狗的 DNA，输出是一种潜在的癌症治疗。*

---

## 一句话讲清问题

肿瘤只是 DNA 里捡到了错别字的正常组织。其中一些错别字会制造出免疫系统从未见过的蛋白。个性化癌症疫苗教免疫系统去猎杀携带那些蛋白的细胞。难的部分是，在可能多达数百个错别字中，弄清楚*哪些错别字*值得作为靶点。

---

## 完整流水线，逐步讲解

### 第 1 步 — 样本采集（诊所）

一位兽医肿瘤医生采集两个样本：
- 一份**肿瘤活检**（一小块癌变组织）
- 一份**血液样本**（同一患者的健康 DNA——"正常"基线）

两者都送去测序实验室。

---

### 第 2 步 — DNA 测序（实验室）

实验室运行**全外显子组测序（WES）**——一个逐字母读取所有蛋白编码区域 DNA 的过程。输出是一个 `.FASTQ` 文件：本质上是数十亿条短 DNA 片段（reads），每条约 150 个字母长。

把它想象成把基因组撕成碎纸屑，然后读取每一片。你最终得到两堆碎纸屑——一堆来自肿瘤，一堆来自血液。

> **为什么需要肿瘤和血液两者？** 你需要血液样本作为参照。没有它，你无法判断一个突变是真实的癌症突变，还是这只狗与生俱来的自然遗传变异。

---

### 第 3 步 — 比对（生物信息学）

软件把每条短 read 映射回参考基因组（对狗来说：**CanFam4**，标准犬基因组）。这就像把撕碎的纸屑重新拼回原始文档。

使用的工具：**BWA-MEM2**、**Samtools**、**Picard**

输出：一个 `.BAM` 文件——reads，现在被定位在基因组上。

> *这一步对 Project Rosie 来说是 Phase 2。我们从第 4 步开始。*

---

### 第 4 步 — 变异检测（生物信息学）

软件把肿瘤 `.BAM` 与血液 `.BAM` 比较，标记出肿瘤 DNA 与正常 DNA 不同的每一个位置。这些差异就是体细胞突变——癌症特有的错别字。

使用的工具：**GATK Mutect2**、**VarScan2**

输出：一个 **`.VCF` 文件**（Variant Call Format，变异调用格式）——一份每个突变的结构化列表：染色体、位置、正常碱基是什么、肿瘤把它改成了什么。

> **Project Rosie 的流水线从这里开始。**

---

### 第 5 步 — VEP 注释（生物信息学）

一个原始 VCF 只说"在位置 X，C 变成了 T"。它不说这在生物学上意味着什么。**VEP（Variant Effect Predictor，变异效应预测器）**把每个突变对照基因数据库查询并注释：

- 影响了哪个基因？
- 这是否改变了该基因产生的蛋白？
- 蛋白变化具体长什么样？（例如 `p.Asp2581His` = 位置 2581 的氨基酸从天冬氨酸变成了组氨酸）
- 这个突变在编码区？在内含子？在下游？

这一步还添加了 pVACseq 所需的两个关键插件：
- **Wildtype**：原始（未突变）的蛋白序列
- **Downstream**：突变后的蛋白序列

输出：一个**注释后的 VCF**——同一个文件，现在每一行都带上了生物学上下文。

使用的工具：**Ensembl VEP**（通过 Docker 运行，使用 CanFam4 缓存处理犬类数据）

---

### 第 6 步 — 新抗原预测（我们的流水线：pVACseq + NetMHCpan）

这是 Project Rosie 的核心。对于每个注释后的突变，我们需要回答：*免疫系统会注意到它吗？*

**pVACseq**（来自华盛顿大学 Griffith 实验室）通过三个子步骤完成这件事：

**6a — 肽生成**
对于每个突变，pVACseq 取变化位置周围一个 21 个氨基酸的窗口，并在其上滑动，生成长度为 8、9、10、11 的所有可能肽片段。这些是候选*新抗原*——免疫系统可能识别的蛋白片段。

**6b — MHC 结合预测**
每个肽都被提交给 **NetMHCpan**——一个在数百万个湿实验结合实验上训练的深度学习模型。它预测每个肽会与患者特定的 **HLA 等位基因**（免疫系统把肽呈递给 T 细胞的"锁"分子）结合得多紧。

输出是一个以纳摩尔（nM）为单位的 **IC50 分数**：
- < 50 nM = 强结合者 → 值得考虑
- 50–500 nM = 中等结合者 → 边缘
- > 500 nM = 弱结合者 → 免疫系统可能忽略它

**6c — 输出**
一个巨大的 TSV 文件，每个肽-等位基因组合一行。在 HCC1395 基准数据集上：955 个突变 → **191,645 行**。

---

### 第 7 步 — 评分与排序（我们的流水线：scoring.py）

pVACseq 的输出巨大且未排序。我们的 `scoring.py` 应用：

**硬过滤器**（任一不通过即剔除）：
- IC50 > 500 nM → 太弱，丢弃
- 肿瘤 VAF < 1% → 突变在肿瘤中几乎不存在，很可能是噪声

**幸存者的综合分数**（越高 = 越好的疫苗候选）：
```
score = 0.50 × 结合强度 (IC50, 对数缩放)
      + 0.30 × 免疫原性 (T 细胞激活概率)
      + 0.20 × VAF (突变的克隆性——存在于更多肿瘤细胞中 = 更好的靶点)
```

输出：一个 **JSON 文件**，含前 20 个排序候选、所有元数据，以及可视化图表的路径。

---

### 第 8 步 — Gemma 4（M2，尚未构建）

JSON + 两张 PNG 图表送入 Gemma 4，它：
- 视觉解读结合亲和力图
- 在一个 256K 上下文窗口中跨所有候选推理
- 为兽医肿瘤医生撰写一份白话临床报告
- 生成 mRNA 合成规格书

---

### 第 9 步 — mRNA 设计（M3，尚未构建）

顶级候选被组装成一段多表位 mRNA 疫苗序列，使用 Biopython 和犬类密码子使用表为犬类生物学做密码子优化。

---

## 为什么我们从 VCF 开始

我们刻意决定**从第 4 步（VCF 文件）开始流水线**，而不是从原始测序 reads 开始。原因如下：

1. **测序实验室已经产出 VCF。** 任何临床测序工作流都会输出一个。我们不需要重做那部分工作。
2. **第 1–3 步是已解决的问题。** BWA-MEM2、GATK 和 Picard 是成熟、文档完善的工具。重建它们只会增加数月工作而无任何新意。
3. **难而未解决的问题是第 5–8 步。** 从 VCF 到一份临床可执行的排序列表——那才是兽医肿瘤学的空白所在。这正是 Project Rosie 要解决的。
4. **范围。** 对于 Gemma4Good 黑客松，我们只有 10 天。从 VCF 开始让我们能交付一个真实的东西，而不是把全部时间花在管道铺设上。

第 1–3 步将在 Phase 2 转向完整临床部署时集成。

---

## 验证数据集

当前所有测试使用 **HCC1395**——生物信息学社区广泛使用的人类乳腺癌基准数据集。它包含来自一位真实乳腺癌患者的配对肿瘤/正常全外显子组测序，并已用 VEP 预注释。你在我们结果中看到的 955 个突变和 191,645 个表位来自这个特定数据集。

真实患者样本会产生不同的数字。流水线能处理任何有效的注释 VCF。

## 术语表

| 术语 | 白话解释 |
|---|---|
| VCF | 肿瘤中发现的突变的电子表格 |
| 肽 / 表位 | 免疫系统可识别的短蛋白片段（8–11 个氨基酸） |
| HLA 等位基因 | 患者免疫识别分子的特定"锁"形状——每个人独一无二 |
| IC50 (nM) | 肽-HLA 契合得多紧。越低 = 越紧 = 越好的疫苗候选 |
| VAF（变异等位基因频率） | 肿瘤细胞中携带这个突变的比例。越高 = 有更多肿瘤细胞可攻击 |
| NetMHCpan | 预测肽-HLA 结合强度的深度学习模型 |
| pVACseq | 编排肽生成 + NetMHCpan 调用的工具 |
| 新抗原 | 存在于肿瘤中但不存在于健康细胞中的蛋白片段——免疫系统的靶点 |
| mRNA 疫苗 | 一种向患者自身细胞递送指令、让其产生新抗原从而触发免疫反应的疫苗 |
