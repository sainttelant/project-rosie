从 DNA 到候选疫苗 —— 完整流程解析

写给没有生物学背景的读者。如果你是软件工程师，可以把它理解为：追踪一次请求在分布式系统中的流转——只不过这里的数据是一只狗的 DNA，而产出是一种潜在的癌症治疗方案。

一句话说清问题

肿瘤不过是正常组织的 DNA 里出现了"错别字"。其中一些错别字会制造出免疫系统从未见过的蛋白质。个性化癌症疫苗的作用，就是教会免疫系统去追杀携带这些蛋白质的细胞。难点在于：从可能多达数百个"错别字"里，判断出哪些值得靶向。

完整流水线，步步拆解

第 1 步 —— 样本采集（临床端）

兽医肿瘤学家会采集两份样本：
• 一份肿瘤活检（取一小块癌变组织）

• 一份血液样本（来自同一只患犬的健康 DNA —— 即"正常"基线）

两份样本一起送往测序实验室。

第 2 步 —— DNA 测序（实验室端）

实验室执行全外显子组测序（WES, Whole Exome Sequencing）——逐个读取所有蛋白质编码区域的 DNA 字母。产出是一个 .FASTQ 文件：本质上是数十亿条极短的 DNA 片段（reads），每条约 150 个字母长。

可以把它想象成：把基因组丢进碎纸机，然后逐片念出上面的字。最后你会得到两堆碎纸屑——一堆来自肿瘤，一堆来自血液。

为什么要同时测肿瘤和血液？ 你需要血液样本作为参照。没有它，你就无法判断某个突变到底是真正的癌症突变，还是这只狗天生携带的自然遗传变异。

第 3 步 —— 序列比对（生物信息学）

软件把每一条短 read 映射回参考基因组（犬类对应的是 CanFam4，标准犬参考基因组）。这就像把碎纸屑重新拼回原始文件。

使用工具：BWA-MEM2、Samtools、Picard

产出：一个 .BAM 文件——所有 read 现在都定位到了基因组上的具体位置。

这一步属于 Project Rosie 的第二阶段。我们从第 4 步开始。

第 4 步 —— 变异检测（生物信息学）

软件将肿瘤的 .BAM 与血液的 .BAM 做对比，标记出肿瘤 DNA 与正常 DNA 存在差别的每一个位点。这些差异就是体细胞突变——癌症特有的"错别字"。

使用工具：GATK Mutect2、VarScan2

产出：一个 .VCF 文件（Variant Call Format，变异调用格式）——一份结构化的突变清单：染色体、位置、原本的碱基是什么、肿瘤把它改成了什么。

这是 Project Rosie 流水线的起点。

第 5 步 —— VEP 注释（生物信息学）

原始 VCF 只会告诉你"在第 X 个位置，C 变成了 T"，并不会说明这在生物学上意味着什么。VEP（Variant Effect Predictor，变异效应预测器）会把每个突变拿到基因数据库中查询并注释：

• 影响了哪个基因？

• 这个突变是否改变了该基因所产生的蛋白质？

• 蛋白质的具体变化是什么？（例如 p.Asp2581His = 第 2581 位氨基酸由天冬氨酸变成了组氨酸）

• 这个突变位于编码区？内含子？还是下游区域？

这一步还会补上 pVACseq 所必需的两个关键插件信息：
• Wildtype（野生型）：原始的（未突变的）蛋白质序列

• Downstream（下游型）：突变后的蛋白质序列

产出：一个带注释的 VCF——还是同一个文件，但每一行都多了生物学上下文。

使用工具：Ensembl VEP（通过 Docker 运行，使用犬类数据专用的 CanFam4 缓存）

第 6 步 —— 新抗原预测（我们的流水线：pVACseq + NetMHCpan）

这是 Project Rosie 的核心。对每一个已注释的突变，我们需要回答：免疫系统会注意到它吗？

pVACseq（来自华盛顿大学 Griffith 实验室）分三个子步骤完成这件事：

6a —— 肽段生成
对每个突变，pVACseq 取变异位点周围 21 个氨基酸的窗口，在窗口内滑动，生成长度为 8、9、10、11 的所有可能肽段片段。这些就是候选新抗原——免疫系统可能识别的蛋白质碎片。

6b —— MHC 结合预测
每一条肽段都会被提交给 NetMHCpan——一个基于数百万次湿实验结合数据训练而来的深度学习模型。它预测每条肽段与该患犬特定 HLA 等位基因（免疫系统的"锁"分子，负责把肽段呈递给 T 细胞）结合的紧密程度。

产出是一个以纳摩尔（nM）为单位的 IC50 分数：
• < 50 nM = 强结合 → 值得考虑

• 50–500 nM = 中等结合 → 边缘情况

• \> 500 nM = 弱结合 → 免疫系统大概会无视它

6c —— 输出
一个巨大的 TSV 文件，每一条"肽段-等位基因"组合占一行。在 HCC1395 基准数据集上：955 个突变 → 191,645 行。

第 7 步 —— 打分与排序（我们的流水线：scoring.py）

pVACseq 的输出庞大且无序。我们的 scoring.py 会施加：

硬性过滤（任一不达标即被剔除）：
• IC50 > 500 nM → 结合太弱，丢弃

• 肿瘤 VAF < 1% → 该突变在肿瘤中几乎不存在，很可能是噪声

综合评分（针对存活下来的候选，分数越高越适合做疫苗）：

score = 0.50 × 结合强度（IC50，取对数缩放）
      + 0.30 × 免疫原性（激活 T 细胞的概率）
      + 0.20 × VAF（该突变的克隆程度 —— 存在于越多肿瘤细胞中，靶点越好）


产出：一个 JSON 文件，包含排名前 20 的候选、全部元数据，以及可视化图表的路径。

第 8 步 —— Gemma 4（M2，尚未构建）

JSON 加两张 PNG 图表会被送入 Gemma 4，由它完成：
• 从视觉上解读结合亲和力图表

• 在 256K 的超长上下文窗口中对所有候选中进行统一推理

• 为兽医肿瘤学家撰写一份通俗语言的临床报告

• 生成 mRNA 合成规格说明

第 9 步 —— mRNA 设计（M3，尚未构建）

排名靠前的候选会被组装成一段多表位 mRNA 疫苗序列，并使用 Biopython 与犬类密码子使用表，针对犬类生物学特性做密码子优化。

为什么我们从 VCF 起步

我们做了一个刻意的选择：从第 4 步（VCF 文件）而不是从原始测序 read 开始搭建流水线。原因如下：

1. 测序实验室本来就会产出 VCF。 任何临床测序工作流都会输出它，我们没必要重做这部分工作。
2. 第 1–3 步已经是解决的问题。 BWA-MEM2、GATK 和 Picard 都是成熟且有完善文档的工具。重建它们只会多花几个月时间，且不带来任何新意。
3. 真正困难、尚未解决的问题在第 5–8 步。 如何从一份 VCF 得到一份临床上可执行的排序清单——这才是兽医肿瘤学领域的空白，也正是 Project Rosie 要解决的问题。
4. 范围考量。 Gemma4Good 黑客松只有 10 天时间。从 VCF 起步能让我们交付真实可用的东西，而不是把全部时间耗在管道搭建上。

第 1–3 步将在第二阶段、即我们转向全面临床部署时再集成进来。

验证数据集

目前所有测试都基于 HCC1395——生物信息学社区广泛使用的人类乳腺癌基准数据集。它包含来自一位真实乳腺癌患者的配对肿瘤/正常全外显子组测序数据，并已预先完成 VEP 注释。你在我们结果中看到的 955 个突变与 191,645 个表位，均来自这一特定数据集。

真实患者样本会产生不同的数字。该流水线可处理任何有效的、带注释的 VCF。
